# 目標方位へ旋回・静止・撮影する機能：実装仕様と実機導入手順

## 1. 実装結果と適用範囲

このリポジトリに、FS90Rとタイヤをリアクションホイールとして使い、ICM-42688の相対ヨー角・ヨー角速度をフィードバックして、目標方位へ有限角だけ旋回し、整定後に1枚撮影する機能を実装した。

実装済みの処理系列は次のとおりである。

```text
地上コマンド
  → 開始条件の確認
  → 目標角と現在角の最短角度誤差
  → 目標機体角速度（外側ループ）
  → ホイール速度指令の増減（内側ループ）
  → FS90R PWM
  → 機体の反作用旋回
  → 角度±3°かつ角速度±0.8°/sを連続1秒確認
  → HOLDを維持したままカメラ撮影
  → QQVGA RGB565フレームを無圧縮送信
```

この実装は「実機で必ず所定精度を達成した」と保証するものではない。慣性比、支持摩擦、糸のねじり、サーボ中立、PWM–回転数特性が未測定だからである。既定ゲインはSILSで安定性を確認した初期値であり、自由回転実験の前に本書の固定機体試験と段階試験が必要である。ゼミ公式仕様は、開発中の自由回転を避け、SILSで作り込んだ後に管理された「打ち上げ」で確認するよう求めている。[^1]

連続回転が止まる理由、偏心・傾斜・摩擦・糸ねじりのモデル、慣性計測法は `REACTION_WHEEL_ROTATION_RESEARCH.md` に詳述している。本書は今回の有限角旋回実装に焦点を絞る。

## 2. 対象ハードウェアと回路上の制約

公式構成は、Pico W、GP11のPWMで駆動するFS90R、I2C0（GP20/21）のICM-42688、MCP3008 CH4へ接続されたフォトリフレクタである。機体は糸とハンドスピナーを介して吊られ、鉛直ヨー1軸を模擬する。[^1][^2][^3]

MAIN回路図ではFS90Rの電源はVBAT直結である。したがって、電池電圧低下に伴って最高回転数、加速能力、停止中立が変化する。モータ電流センサやトルク制御ドライバはないため、Picoが与えられる操作量はトルクではなく連続回転サーボのPWMパルス幅、実質的には速度指令である。[^4]

FS90Rの仕様値は、指令700–2300 µs、中立1500±45 µs、デッドバンド90 µs、無負荷速度110 rpm（4.8 V）/130 rpm（6 V）である。中立公差だけでも無視できないため、1500 µsを送れば実機が必ず完全停止するとは限らない。[^5]

## 3. 物理法則と制御の符号

機体角を `θ`、機体角速度を `Ω`、機体に対するホイール相対角速度を `ω`、機体慣性を `J_b`、ホイール慣性を `J_w` とする。全角運動量は

```text
H = (J_b + J_w) Ω + J_w ω
```

であり、外部ヨートルク `τ_ext` に対して

```text
(J_b + J_w) Ωdot + J_w ωdot = τ_ext                 (1)
```

となる。外部トルクが小さい短時間では、ホイールを正方向へ加速すると機体は負方向へ加速する。機体を止めるには、ホイールを反対向きへ加速、すなわち旋回中のホイールを減速する必要がある。これは「ホイールを回す」ことではなく、「ホイール角運動量を変化させる」ことが機体トルクを生む、という意味である。角運動量保存則の一般式は、外部トルクがゼロなら全角運動量が保存されることを示す。[^6][^7]

実機では

```text
τ_ext = -τ_c sign(Ω) - bΩ - k_t(θ - θ_0) + τ_contact + τ_tilt
```

のような支持摩擦、粘性抵抗、糸・配線のねじり、接触、傾斜・偏心に起因するトルクがある。従って開ループの一定PWMでは目標角に停止できない。角度と角速度を連続測定し、誤差が残ればホイール速度を変え続ける閉ループ制御が必要である。

## 4. 採用した制御則

### 4.1 最短角度誤差

絶対目標 `θ_target` と推定角 `θ` の差は次の範囲へ折り返す。

```text
eθ = wrap180(θ_target - θ) ∈ [-180°, +180°]
```

これにより、例えば現在170°、目標-170°なら-340°回るのではなく+20°回る。ちょうど+180°の入力は正方向、-180°は負方向として保持し、相対指令の符号が失われないようにした。

### 4.2 角度外側ループ

```text
Ω_ref = clamp(Kθ eθ, -Ω_max, +Ω_max)
```

既定値は `Kθ=0.70 s^-1`、`Ω_max=5 deg/s` である。遠方では最大5 deg/sを目標にし、目標へ近づくほど目標角速度を小さくする。これは急停止を命令せず、自然に減速区間を作る。

### 4.3 角速度内側ループとFS90R指令

FS90Rはトルク指令を受けないため、角速度誤差から要求機体角加速度を作り、その反対符号をホイール速度指令へ積分する。

```text
α_body,req = KΩ (Ω_ref - Ω)
u_wheel[k+1] = clamp(u_wheel[k] - Kw α_body,req Δt, -u_max, +u_max)
```

既定値は `KΩ=1.50 s^-1`、`Kw=3.00`、`u_max=70%`、更新周期20 ms（50 Hz）である。負号は式(1)の反作用を表す。機体を正方向へ加速したいとき、ホイール指令を負方向へ変える。

これはホイールrpmの閉ループではなく、機体の角度・角速度を閉ループにした実用的な近似である。フォトリフレクタのrpmは開始時の停止確認と監視に使い、制御量にはまだ直接使っていない。実測したPWM–rpmモデルを得た後は、`u_wheel`を目標rpmとして内側にホイール速度PIを追加すると再現性が上がる。

### 4.4 整定と撮影

以下を同時に、連続1000 ms満たした場合だけ `SLEW` から `HOLD` へ遷移する。

```text
|eθ| ≤ 3.0°
|Ω|  ≤ 0.8°/s
```

一度でも外れれば整定タイマは0へ戻る。制御周期が100 msを超えて欠落した場合も、その区間を整定時間に数えない。`HOLD` へ入ると撮影要求を1回だけ発行するが、制御は停止しない。撮影の瞬間にサーボを中立へ戻すと、その減速反作用で機体が再び動く可能性があるため、撮影完了後もHOLD制御を維持する設計である。終了は明示的に `SLEW_ABORT` または手動速度指令で行う。

## 5. 実際に期待される動き

正方向へ+30°旋回する例では、符号は次のようになる。ただしFS90Rの取付方向により画面上の正負が逆なら、サーボ指令符号またはセンサ座標系を一度だけ反転する。

| 時相 | 機体 | ホイール | 制御の意味 |
|---|---|---|---|
| 開始直後 | 正方向へ加速 | 負方向へ加速 | 反作用で旋回を開始 |
| 巡航 | 約+5 deg/s | 負方向速度を必要に応じて変化 | 摩擦と速度誤差を補償 |
| 目標接近 | 減速 | 負方向回転を弱める／正方向へ加速 | ホイール運動量変化で機体を制動 |
| 整定 | 角度誤差と角速度が小さい | わずかに増減し得る | 摩擦・ねじりを補償 |
| 撮影 | ほぼ静止 | HOLD指令を維持 | 1秒整定後に1枚取得 |

支持摩擦が大き過ぎる場合は、低いホイール加速度では静止摩擦を越えず機体が動かない。動き始めた直後に飛び出す場合はスティックスリップである。糸ねじりが強い場合は、特定角度から先へ行けない、または目標到達後に戻ろうとする。重心偏心と傾斜がある場合は、角度に同期した速度むらや横揺れが現れる。これらはゲインだけで完全には直せず、機械調整を先に行う。

## 6. ソフトウェア構成

| ファイル | 役割 |
|---|---|
| `attitude_control.c/.h` | 状態機械、角度・角速度制御、整定判定、異常判定 |
| `wheel_sensor.c/.h` | CH4 ADCの適応しきい値、ヒステリシス、1マーカー/回転の周期・rpm推定 |
| `main.c` | 50 Hz制御、500 Hz回転センサ、コマンド、撮影要求、QQVGA RAW送信、TCP切断時安全停止 |
| `telemetry.c/.h` | 制御モード、誤差、目標レート、ホイール指令、整定時間、rpmの収集 |
| `protocol.c/.h` | 制御テレメトリの文字列化、最大メッセージ長768 byte |
| `tests/slew_sils.mjs` | 慣性比・摩擦・方向を振った1軸SILS回帰試験 |

IMUは既存どおりcore 1で200 Hz更新する。core 0では制御50 Hz、フォトリフレクタ500 Hz、サーボ更新50 Hz、ネットワークとカメラ処理を協調実行する。38,400 byteのRAW RGB565送信中は同じTCPストリームへテキスト行が割り込まないよう、ACK・イベント・テレメトリをキューへ退避する。

## 7. 状態機械と異常時動作

```text
IDLE ── SLEW_CAPTURE ──> SLEW ── 連続整定1秒 ──> HOLD ──> 撮影1回
                              │                    │
                              ├─ IMU不正 ─────────┤
                              ├─ 90秒超過 ────────┤──> FAULT → 指令0
                              └─ 飽和押付1.5秒 ───┘

SLEW/HOLD ── SLEW_ABORT・TCP切断/受信異常 ──> ABORTED → 指令0
```

`FAULT,SATURATION` は実rpm飽和ではなく、計算上のホイール指令が±70%を越える方向へ1.5秒押し続けたことを表す。実回転数による飽和判定は、マーカー検出の信頼性と最大rpmを実測してから追加するべきである。

サーボ指令0は既存実装の1500 µsを意味する。FS90Rの中立公差により完全停止しない個体では、自由回転試験前に中立値の校正が必須である。通信断時に0指令へ戻すのはフェイルセーフだが、ホイール減速そのものが一時的に機体を回す点には注意する。緊急停止とは「モータへの継続指令を止める」意味で、機体を瞬時に静止させる意味ではない。

## 8. 地上コマンド仕様

各コマンドは改行終端で送る。

### 8.1 原点設定

```text
ANGLE_RESET
```

現在の積分ヨー角を0°にする。これは磁北などの絶対方位ではない。機体を既知の基準方向へ手で固定して静止させ、IMU校正完了後に実行する。制御中は拒否される。

### 8.2 絶対相対方位への旋回・撮影

```text
SLEW_CAPTURE,30
```

直近の `ANGLE_RESET` 原点に対する+30°を目標とし、最短方向へ旋回する。許容入力は±3600°だが、誤差は±180°へ折り返すため、用途上は通常±180°以内を使う。

### 8.3 現在位置からの相対旋回・撮影

```text
SLEW_REL_CAPTURE,-45
```

受信時の現在角から-45°を目標とする。範囲は-180～+180°である。

### 8.4 状態確認と中止

```text
SLEW_STATUS
SLEW_ABORT
```

状態応答にはmode、fault、target、error、rate、wheel command、capture済みフラグが入る。中止は撮影要求を取り消し、サーボ目標を0へ戻す。

### 8.5 実機調整用ゲイン

```text
SLEW_CONFIG,angle_gain,rate_gain,wheel_gain,max_rate,max_wheel
```

例：

```text
SLEW_CONFIG,0.50,1.00,2.00,3.00,50.00
```

範囲は順に0.05–2、0.1–5、0.1–10、0.5–30 deg/s、10–90%である。旋回中は変更できず、再起動すると既定値へ戻る。最初は `max_rate` と `max_wheel` を低くし、振動がないことを確認してから上げる。

開始時に、制御実行中、カメラ処理中、IMU未校正、手動ホイール指令が非0、または有効なrpm推定が5 rpmを超える場合は旋回を開始しない。ストリーミングは旋回開始時に停止する。

## 9. テレメトリの読み方

追加フィールドは次のとおりである。

| フィールド | 意味 |
|---|---|
| `wheel_rpm` | マーカー周期から求めた符号付きrpm。方向未確定・検出無効ならNA |
| `control_mode` | IDLE/SLEW/HOLD/ABORTED/FAULT |
| `control_fault` | NONE/IMU/TIMEOUT/SATURATION |
| `control_target_deg` | 目標相対ヨー角 |
| `control_error_deg` | ±180°へ折り返した角度誤差 |
| `control_rate_ref_dps` | 外側ループの目標機体角速度 |
| `control_wheel_command_percent` | 積分されたFS90R指令 |
| `control_elapsed_ms` | 旋回開始からの経過時間 |
| `control_settled_ms` | 現在連続して整定窓内にいる時間 |
| `control_capture_issued` | HOLD後の撮影要求を発行済みなら1 |

成功時は概ね `SLEW → HOLD` のイベントが届き、`control_settled_ms` が1000へ達し、続いて `FRAME,160,120,RGB565,38400,...` が送信される。`HOLD`後も誤差が増えるなら、ねじり復元力、サーボ中立ずれ、ゲイン不足、ホイール飽和を疑う。

## 10. 導入・校正・試験手順

### Phase A：機械と電源（自由回転させない）

1. 支持軸とリアクションホイール軸を鉛直にする。
2. 重心を支持軸へ寄せ、静止時のroll/pitchを記録する。
3. 糸・電線のねじれ、機体・治具の接触、ハンドスピナーの偏荷重を除く。
4. 電池電圧を測り、サーボ動作時の電圧降下とPicoリセットがないか確認する。
5. ホイールを拘束したままストールさせない。FS90Rの仕様上ストール電流は6 Vで約650 mAである。[^5]

### Phase B：固定機体でサーボと回転センサを同定

1. 機体を確実に固定する。
2. 手動指令を0にし、ホイールが止まるパルス幅を電池電圧別に測る。現状コードの中立は1500 µs固定なので、個体差が大きい場合はこの値を実機値へ変更する。
3. 正負それぞれで小さい指令から段階的に上げ、定常rpm、立上り時間、停止時間を記録する。
4. フォトリフレクタの生ADCを確認し、マーカー有無のコントラストが80 count以上あるか確認する。
5. マーカーを1個だけ使う。複数なら `rpm=60/周期` の換算にマーカー数補正が必要である。
6. 方向別の最大rpm、中立デッドバンド、最小安定rpmをSILSモデルへ反映する。

### Phase C：SILS

```powershell
node tests/slew_sils.mjs
```

試験は目標-90/-30/0/+30/+90°、慣性比 `J_w/(J_b+J_w)=0.02/0.03/0.05`、抵抗係数0/0.02/0.05の組合せを検証する。弱いアクチュエータ条件でSATURATIONへ入ること、±180°の符号も検証する。現在の回帰試験結果は48 assertionすべて成功である。

### Phase D：管理された自由回転試験

ゼミの試験制約に従い、管理された打ち上げ時のみ実施する。[^1]

1. `ANGLE_RESET` 後、まず±5°、`max_rate=1 deg/s`、`max_wheel=20%`で試す。
2. 正目標で機体が負へ動くなら、サーボとIMUの符号整合を修正して中止する。
3. ±5°が過大振動なく成功してから±15°、±30°へ広げる。
4. 正負を必ず別々に試し、到達時間、最大角速度、オーバーシュート、整定時間、最終誤差、最大指令、rpm、roll/pitchを保存する。
5. 振動する場合はまず `wheel_gain`、次に `rate_gain` を下げる。遅いが単調なら `angle_gain` または `max_rate` を少し上げる。
6. 目標近傍で止まらない場合は中立ずれ、静止摩擦、糸ねじりを調べ、ゲインだけで押し切らない。
7. `SATURATION`なら要求角、摩擦、慣性比、最大指令を見直す。上限を安易に90%へ上げる前にホイールrpm余裕を確認する。

## 11. チューニング判断表

| 症状 | 第一候補 | 対処 |
|---|---|---|
| 機体が動かない | 静止摩擦、慣性比小、指令不足 | 機械調整、`wheel_gain`を小刻みに増加 |
| 大きく往復振動 | `wheel_gain`/`rate_gain`過大、遅延 | 両ゲインを下げ、`max_rate`も下げる |
| ゆっくり目標へ近づく | `angle_gain`/`max_rate`が低い | 安定を確認し少しずつ増加 |
| 目標を通過し続ける | 制動不足、中立ずれ | `rate_gain`調整、中立校正、摩擦モデル確認 |
| HOLDでじわじわずれる | ジャイロバイアス、ねじり、飽和 | 原点・IMU温度安定、機械調整、絶対方向観測追加 |
| 一周周期の速度むら | 重心偏心、傾斜、擦れ | バランス・水平・軸合わせを修正 |
| rpmがNA | コントラスト不足、マーカー/距離不良 | 生ADC、遮光、センサ距離を確認 |
| カメラ前後で姿勢が乱れる | 電源降下、処理遅延、振動 | 電源ログ、制御deadline、固定を確認 |

ゲイン調整より先に、`J_w/J_b`、摩擦、ねじり、中立、PWM–rpmを測る。制御不能な機械条件を高ゲインで覆うと、飽和、発振、ギヤ損傷、電源降下につながる。

## 12. 検証済み事項と残作業

検証済み：

- 制御モジュールと回転センサモジュールはARM GCCの `-Wall -Wextra -Werror` 構文検査を通過。
- 統合後の `main.c` を含む変更Cファイルも同じクロスコンパイラで個別検査を通過。
- 1軸SILSの48 assertionが成功。
- QQVGA RAW RGB565の段階送信と制御テキストキューを旋回制御と統合し、画像本体へテレメトリ行が割り込まない構成にした。

未検証・残作業：

- CMake/Ninjaの最終リンクは完了し、新しい `build/pico_satellite_controller.uf2` を生成済みである。
- 実機の自由回転、撮影時の指向精度、整定時間、電池電圧依存は未試験。
- FS90R個体中立1500 µsの実測補正は未実装。
- フォトリフレクタは1マーカー/回転を仮定し、実rpmを制御ループにはまだ使用していない。
- 積分ジャイロ角は長時間ドリフトする。絶対方位が必要なら、既知初期姿勢に加えて太陽センサまたは画像認識による低周波補正を追加する。

合格基準は実験前に数値で固定する。最低限、目標誤差、撮影時角速度、整定時間、許容オーバーシュート、タイムアウト率、通信断時挙動、電池最低電圧を定義する。本実装の既定整定判定は±3°、±0.8 deg/s、1秒であり、ミッション要求がこれより厳しい場合はセンサ誤差を含む検証後に変更する。
